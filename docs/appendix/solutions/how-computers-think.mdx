# เฉลย — คอมพิวเตอร์คิดยังไง

:::warning ลองเองให้สุดก่อน

การติดแล้วคิดต่ออีก 15 นาที ให้ผลต่อความจำมากกว่าการเปิดเฉลยทันทีมาก

:::

เฉลยทุกข้ออธิบาย**วิธีคิด** ไม่ใช่แค่คำตอบ ข้อที่ทำได้หลายทางจะแสดงมากกว่าหนึ่งวิธี

## ง่าย

### ข้อ 1 — ค่าเฉลี่ยของ 8 กับ 12

<PythonRunner initialCode={`print((8 + 12) / 2)`} expectedOutput="10.0" />

**วิธีคิด:** ปัญหาเดิมคือเครื่องหารก่อนบวก เพราะการคูณและการหารถูกทำก่อนการบวกและการลบเสมอ
วงเล็บคือวิธีบอกว่า "ทำในนี้ก่อน"

สังเกตว่าผลลัพธ์เป็น `10.0` ไม่ใช่ `10` เพราะการหารในภาษา Python ให้ผลเป็นเลขทศนิยมเสมอ
แม้จะหารลงตัว เรื่องนี้จะอธิบายเต็ม ๆ ในบท 0.5

### ข้อ 2 — เดาผลลัพธ์ของ `2 + 3 * 4`

คำตอบคือ **14**

**วิธีคิด:** เครื่องอ่านเป็น `2 + (3 * 4)` = `2 + 12` = `14`
ไม่ใช่ `(2 + 3) * 4` = `20`

ถ้าคุณเดาเป็น 20 แสดงว่าคุณอ่านจากซ้ายไปขวาแบบที่มนุษย์อ่านประโยค
ซึ่งเป็นความเข้าใจผิดที่พบบ่อยมาก และเป็นสาเหตุของบั๊กที่หายากประเภทหนึ่ง
เพราะโค้ดจะดู "ถูก" ทุกครั้งที่กวาดตาอ่าน

### ข้อ 3 — ใช้ 2, 3, 4 ให้ได้ 20

<PythonRunner initialCode={`print((2 + 3) * 4)`} expectedOutput="20" />

**ทำได้สองแบบ** และทั้งสองแบบถูก

```python
print((2 + 3) * 4)   # 20
print(4 * (2 + 3))   # 20
```

**วิธีคิด:** 20 แยกตัวประกอบได้เป็น 4 × 5 เรามีเลข 4 อยู่แล้ว
เหลือแค่ทำ 5 จาก 2 กับ 3 ซึ่งก็คือ 2 + 3

การไล่ย้อนจากคำตอบกลับมาหาวิธี เป็นเทคนิคที่ใช้ได้บ่อยกว่าที่คิด

## กลาง

### ข้อ 4 — จุดกำกวมใน "แจ้งเตือนนักเรียนที่คะแนนต่ำ"

มีมากกว่าสามจุด นี่คือตัวอย่าง

| จุดกำกวม | ถ้าเครื่องเลือกคนละทางกับที่เราคิด |
|---|---|
| "ต่ำ" คือต่ำกว่าเท่าไร | ตั้งไว้ที่ 50 แต่เครื่องใช้ 60 → นักเรียนที่ผ่านโดนแจ้งเตือนด้วย |
| คะแนนของวิชาไหน รวมทุกวิชาหรือแยกวิชา | เด็กที่เก่งเก้าวิชาแต่ตกวิชาเดียว อาจไม่ถูกแจ้งเพราะค่าเฉลี่ยรวมยังสูง |
| "แจ้งเตือน" คือส่งหาใคร | ตั้งใจส่งหานักเรียน แต่เครื่องส่งหาผู้ปกครองทุกคน |
| นักเรียนที่ยังไม่มีคะแนน (ลาป่วย) นับว่าต่ำไหม | ถูกนับเป็น 0 แล้วโดนแจ้งเตือนทั้งที่ยังไม่ได้สอบ |
| แจ้งกี่ครั้ง | ตั้งใจให้แจ้งครั้งเดียว แต่เครื่องแจ้งทุกวันจนกว่าคะแนนจะขึ้น |

**สิ่งที่ข้อนี้อยากให้เห็น:** ความกำกวมไม่ได้ทำให้เครื่องหยุดถาม
มันทำให้เครื่องเลือกไปเองเงียบ ๆ แล้วเราจะรู้ตอนที่ผลลัพธ์ออกมาแล้ว

### ข้อ 5 — หน่วยความจำต่างจากที่เก็บข้อมูลตรงไหน

| | หน่วยความจำ (RAM) | ที่เก็บข้อมูล (storage) |
|---|---|---|
| ความเร็ว | เร็วมาก | ช้ากว่ามาก |
| ปิดเครื่องแล้ว | หายหมด | ยังอยู่ |
| ใช้เก็บอะไร | สิ่งที่กำลังใช้ตอนนี้ | ทุกอย่างที่ต้องเก็บไว้ |

**ตัวอย่างในชีวิตจริงที่สังเกตเห็นได้เอง:**

- พิมพ์งานค้างไว้แล้วไฟดับ งานที่ยังไม่ได้กดบันทึกหายไป แต่ไฟล์ที่เคยบันทึกแล้วยังอยู่ครบ
- เปิดโปรแกรมใหญ่ ๆ ครั้งแรกจะช้า (ต้องขนจากตู้ขึ้นโต๊ะ) แต่พอปิดแล้วเปิดใหม่ทันทีจะเร็วขึ้น
- เปิดแท็บเยอะ ๆ แล้วเครื่องอืด เพราะโต๊ะเต็ม ไม่ใช่เพราะตู้เต็ม

### ข้อ 6 — โปรแกรมเดิมให้ผลลัพธ์ผิดโดยโค้ดไม่เปลี่ยน

**เป็นไปได้** และเกิดขึ้นจริงบ่อยมาก

สาเหตุที่เป็นไปได้ เช่น

- **ข้อมูลที่ป้อนเข้าเปลี่ยนรูปแบบ** เช่น เดิมวันที่มาเป็น `2024-01-05` แล้ววันหนึ่งเปลี่ยนเป็น `05/01/2024`
- **เวลาเดินไป** เช่น โปรแกรมเก็บปีเป็นเลขสองหลัก พอขึ้นปีใหม่แล้วเรียงลำดับผิด
- **สิ่งที่โปรแกรมพึ่งพาเปลี่ยน** เช่น เว็บที่ไปดึงข้อมูลมาเปลี่ยนโครงสร้างหน้า
- **ปริมาณข้อมูลโตขึ้นจนเกินขีดจำกัด** ที่ตอนเขียนไม่ได้คิดว่าจะถึง

**สิ่งที่ข้อนี้อยากให้เห็น:** โปรแกรมไม่ได้อยู่ลอย ๆ มันตั้งอยู่บนข้อสมมติหลายอย่าง
เกี่ยวกับโลกรอบตัว โค้ดไม่เปลี่ยน แต่โลกเปลี่ยนได้

<Callout type="note">
  ข้อสมมติที่ว่า "ปีมีสองหลักก็พอ" คือต้นเหตุของปัญหา Y2K
  ซึ่งทำให้ทั้งโลกต้องไล่แก้โปรแกรมกันก่อนถึงปี 2000

  โปรแกรมพวกนั้นไม่ได้เขียนผิด มันถูกต้องตามข้อสมมติของยุคที่เขียน — แล้วยุคก็เปลี่ยน
</Callout>

## ท้าทาย

### ข้อ 7 — เครื่องที่บวกได้อย่างเดียว จะลบได้ยังไง

**แนวคิดหลัก:** เปลี่ยนการลบให้กลายเป็นการบวก

`7 − 3` เขียนใหม่ได้เป็น `7 + (−3)`

<PythonRunner initialCode={`print(7 + (-3))`} expectedOutput="4" />

คำถามถัดไปคือ แล้วเครื่องเก็บ `−3` ยังไง ในเมื่อมันมีแต่ 0 กับ 1 ไม่มีเครื่องหมายลบ

คำตอบสั้น ๆ คือ มีวิธีเลือกได้ว่าจะให้รหัสบิตชุดไหนแทนจำนวนลบ
และมีวิธีเลือกหนึ่งที่ทำให้ **การบวกตัวแทนของจำนวนลบ ได้ผลเท่ากับการลบพอดี**
โดยวงจรบวกไม่ต้องรู้เลยว่ากำลังบวกจำนวนบวกหรือจำนวนลบอยู่

วิธีนั้นชื่อ <span lang="en">two's complement</span> เราจะเรียนกันจริงจังใน Stage 1

**สิ่งที่ข้อนี้อยากให้เห็น:** เวลาเครื่องมือทำได้แค่อย่างเดียว
ทางออกไม่ใช่การเพิ่มความสามารถให้เครื่องมือ แต่คือการเขียนปัญหาใหม่ให้อยู่ในรูปที่เครื่องมือทำได้
วิธีคิดแบบนี้จะเจอซ้ำอีกหลายครั้งในคอร์สนี้

### ข้อ 8 — รูปภาพถูกเก็บเป็นอะไร

ไม่มีคำตอบตายตัว ข้อนี้ต้องการแค่ให้เดาไปในทางที่ถูก

**แนวทางที่ใกล้เคียง:** รูปหนึ่งรูปคือตารางจุดสีเล็ก ๆ จำนวนมาก
แต่ละจุดบอกความเข้มของสีไว้เป็นตัวเลข พอมีตัวเลขครบทุกจุด ก็ประกอบกลับเป็นรูปได้

ถ้าคุณเดาว่า "น่าจะเก็บเป็นตัวเลขชุดหนึ่ง" ถือว่าจับทางถูกแล้ว

ส่วนวิดีโอก็คือรูปหลายรูปเรียงต่อกันตามเวลา บวกกับเสียงซึ่งก็เป็นตัวเลขอีกชุด

รายละเอียดจริงอยู่ใน **บท 0.3** ส่วนเรื่องที่ว่าทำไมทุกอย่างถึงกลายเป็นตัวเลขได้
อยู่ใน **บท 0.2**
